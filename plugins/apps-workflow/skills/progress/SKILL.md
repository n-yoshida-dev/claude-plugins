## やること

1. Bash ツールで次のコマンドを**このまま**実行する（TODO.md を読んで集計するだけで、何も書き換えない）。

   ```bash
   bash ${CLAUDE_PLUGIN_ROOT}/hooks/progress.sh
   ```

   上のパスはスキルの読み込み時にプラグインの置き場所（絶対パス）へ置き換わる。`$` で始まる文字列のまま見えている場合や
   ファイルが無い場合は、`ls ~/.claude/plugins/cache/n-yoshida-dev/apps-workflow/*/hooks/progress.sh` で探し、
   いちばん新しいバージョンのものを `bash` で実行する。それも無ければ「進捗スクリプトが見つからない。
   `/plugin update apps-workflow@n-yoshida-dev` で 1.4.1 以上に更新する」と伝えて終わる

2. 出力された表を、返答の冒頭に**コードブロックのまま**貼る。数値を書き換えない・要約しない・並べ替えない。
   出力が空なら、このリポジトリに TODO.md が無いと伝える

3. そのあと 1〜3 行だけ補足する。

   - 残りが最も多いフェーズと、その中で次に着手するタスク（HANDOFF.md「次セッションで最初にやること」と一致させる）
   - 「あなたの回答待ち」が 1 件以上なら、「次に動くのはユーザー」であることと、その一覧が TODO.md の「確認待ち」節にあること
   - 「タスク未定義」のフェーズがあれば、そのフェーズは設計が済んでから件数が出ること

## なぜシェル埋め込みで集計しないのか

シェル埋め込み（感嘆符の直後にバッククォートで囲んだコマンドを書く、事前実行の構文）は、
ユーザーがスラッシュコマンドで起動したとき会話の前に実行される。許可プロンプトを出せないので、
事前検査に通らないとスキル全体が中止になる（VSCode 拡張・Auto モードで 2026-09-18 に発生）。
本文の指示にしておけば、Bash ツールの通常の許可フローに乗る。

## 表の読み方（ユーザーに聞かれたら）

- 件数は工数ではない。1 タスク = PR 1 本の大きさに揃える規約（TODO.md 冒頭）が前提
- 「新たに見つかったタスク」が増えると、完了しても率は上がらない。バーが動かない理由はここに出る
- 「保留」は急がない持ち越しで、合計に含めない。「確認待ち」はユーザーの回答待ちで、Claude では進められない
