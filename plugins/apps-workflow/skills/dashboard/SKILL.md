# 開発ダッシュボード（作り方の手順）

skill-matrix で 2026-09-26〜27 に作ったもの（PR #47〜#55）を元にした型。決めることを減らして「ポン出し」するためのスキル。
**画面の中身とデザインはリポジトリごとに変えてよい。守るのは下の「方針」だけ。**

## 方針（全リポジトリ共通。ここは変えない）

1. **観測画面であって管理画面ではない。** 正本（TODO.md / HANDOFF.md / logs/decisions.md / git / GitHub / そのリポジトリのデータ）を
   読んで描くだけ。ダッシュボード独自の状態を持たない。人が画面から書き込む機能を付けない。同じ数字を正本と二重に持たない
2. **文章は最低限。説明の文・欄の名前・種類の札は出さず、並びと大きさで読ませる**（横断タスクボードと同じ考え方。本人の方針
   「不要なラベルや補足説明を避け、レイアウトと視覚的な構造で直感的に理解できる UI」2026-10-28）。見出しは「あなた待ち」と固有の指標の名前だけ。
   ただしタスクのタグ（判断・確認・作業・ブロック中）は残す。一覧は 1 項目 1 行（括弧書き・Markdown 記法・2 文目以降を落とす）。
   全文・行番号はマウスを載せるか押したときだけ出す。段落の文章（引き継ぎメモ全文・合意の本文）は最下部の折りたたみに置く
3. **上から「異常の帯 → あなた待ち・進捗と今のタスク → 変更（PR とコミット）・固有の指標 → 折りたたみ」。** 重要なものほど上。
   異常（CI 失敗・検証失敗・引き継ぎの遅れ・取得失敗）は最上段に赤／黄の帯で出し、異常が無いときは帯を出さない。
   正常な状態（CI 成功・作業ツリーがきれい）のためのタイルは置かない。main の CI の結果は、そのコミットの行の先頭の記号で示す
   （CI の実行と最近のコミットは同じ変更なので、別の欄にすると同じ題名が 2 回並ぶ）
4. **状態は記号と色で示す**（✓ 成功 / ✕ 失敗 / ! 注意 / ● 実行中 / – 取得できず）。色だけに頼らない。
   **色は異常にだけ使う**：正常（✓）は灰色、赤い線・赤枠は CI 失敗など「たまにしか起きない」ときだけ。あなた待ちは件数の数字の色で示し、
   種類のタグは「判断」だけ色を付ける。いつも付く色は目立たせる意味を失い、本当の異常を埋もれさせる（2026-09-27 のレビュー）
5. **入口は横断タスクボード（ops）の「開発状況」タブだけで、この画面はカードの「詳しく見る」の行き先**（2026-10-28 本人）。
   ボードは Claude デスクトップの右側（画面の 3 分の 1 ほど）で見るので、**幅 560px 前後で読めることを先に確かめる**。
   ヘッダーは名前（GitHub へのリンク）といつのデータかだけで、「起動方法」「更新」ボタンと自動の再読み込みは置かない。
   ボードに載せるのは ops の `snippets/build_board_dashboards.py`（各リポジトリの `update.mjs` を呼んで写す）。
   手元で単独に見るときは `node dashboard/update.mjs --serve --open`（開き直すと作り直す）
6. **依存 0・ビルド無し・数ファイル。** Node 標準ライブラリと素の HTML/CSS/JS だけ。生成物（`dashboard/data.js`）は `.gitignore`。
   `data.js` は `window.DASHBOARD_DATA = {...}` の JS にして、`index.html` をダブルクリックで開いても読めるようにする
7. **無いものは黙って飛ばし、壊れているものは画面に出す。** `gh` が無ければ「取得できず」、JSON が壊れていれば赤い帯。握りつぶさない
8. **人が今見る価値のある項目だけ。** 項目数を増やさない。候補は下の「表示項目の選び方」
9. **長い一覧は上位だけ出す。** あなた待ちは各画面で上位 6 件、ハブで上位 3 件。残りは「ほか N 件」で開く（全部並べると下の欄が画面の外に押し出される）

## 手順

### 1. 調べる（10 分）

- `CLAUDE.md` / `HANDOFF.md` / `TODO.md` / `logs/decisions.md` / `.github/workflows/` の有無と形を見る。
  apps 配下のアプリなら全部同じ規約なので、テンプレートの読み取りがそのまま動く
- **そのリポジトリ固有の「人が今見る価値のある数字と状態」を 1〜2 個だけ決める。** 例：データファイルの件数と検証コマンドの成否（skill-matrix）、
  マイグレーションの適用状態、商品データの登録件数、E2E の最終結果。**数十秒かかるコマンドは選ばない**（正本は CI の結果）
- 別セッションが同じチェックアウトで作業中なら、`git worktree add` で別ディレクトリに分けて作業する（ブランチ切り替え・stash をしない）

### 2. テンプレートを写す（5 分）

```bash
mkdir -p dashboard
cp ${CLAUDE_PLUGIN_ROOT}/skills/dashboard/template/update.mjs dashboard/
cp ${CLAUDE_PLUGIN_ROOT}/skills/dashboard/template/index.html dashboard/
cp ${CLAUDE_PLUGIN_ROOT}/skills/dashboard/template/README.md dashboard/
```

上のパスはスキルの読み込み時にプラグインの置き場所（絶対パス）へ置き換わる。`$` で始まる文字列のまま見えている場合は
`ls -d ~/.claude/plugins/cache/n-yoshida-dev/apps-workflow/*/skills/dashboard/template` で探し、いちばん新しいバージョンを使う。

`.gitignore` に次の 2 行を足す。

```
dashboard/data.js
dashboard/data.js.tmp
```

### 3. 固有の指標を書く（10〜20 分）

`dashboard/update.mjs` の **★ の節 `readProjectSpecific()` だけ**を書き換える。返す形はその関数のコメントにある
（`title` / `status`（異常のときだけ見出しの横に出す状態 1 つ）/ `stats`（数字 4 つまで）/ `bars` / `note` / `output` / `alerts` / `human`）。
`index.html` はその形をそのまま描くので、原則触らない。見た目を変えたいときは `index.html` の CSS の変数（`:root`）から変える。
テンプレートより前に作った `update.mjs` で、固有の指標を別の形で持っているリポジトリ（skill-matrix の `d.data`）は、
`index.html` の ★ の関数 `specific()` だけを書き換えて、この形に変換する（`update.mjs` は触らない）。

固有の指標が本当に無いなら `null` のままでよい（固有の指標のカードが出ないだけ）。

### 4. 動かして確かめる（10 分）

```bash
node dashboard/update.mjs                      # data.js ができ、1 行の要約が出る
node dashboard/update.mjs --serve --port 8791  # 配信。--open は付けない（確認はヘッドレスで）
curl -s -X POST http://127.0.0.1:8791/update   # {"ok":true,...}
```

ヘッドレス Chromium があれば（`ls ~/.cache/ms-playwright/chromium_headless_shell-*/chrome-headless-shell-linux64/chrome-headless-shell`）、
560px（ボードで見る幅）と 1280px で撮って見る。無ければ `--dump-dom` 相当の確認をせず、ユーザーに開いてもらう。

```bash
C=$(ls ~/.cache/ms-playwright/chromium_headless_shell-*/chrome-headless-shell-linux64/chrome-headless-shell | tail -1)
"$C" --headless --no-sandbox --disable-gpu --hide-scrollbars --virtual-time-budget=4000 --window-size=1280,1400 --screenshot=/tmp/pc.png http://127.0.0.1:8791/
"$C" --headless --no-sandbox --disable-gpu --hide-scrollbars --virtual-time-budget=4000 --window-size=560,1600 --screenshot=/tmp/board.png http://127.0.0.1:8791/
```

確かめること：描画エラーが無い（`#err` が hidden）／一覧が 1 行に収まっている／560px で横にはみ出さない／
`git status` に `data.js` が出ない／ファイルを直接開いても描ける（`file://`）。終わったらプロセスを止める。

### 5. 文書に 1 節ずつ足す（5 分）

- そのリポジトリの `CLAUDE.md` に「## 開発ダッシュボード（`dashboard/`）」を 5 行以内で。起動コマンド、独自の状態を持たないこと、
  「TODO の見出し規約・HANDOFF の節名・CI のジョブ名を変えたら `update.mjs` も直す」の 1 行
- `HANDOFF.md` の動作確認コマンドに `node dashboard/update.mjs --serve --open` を 1 行
- `TODO.md` に完了条件つきで 1 タスク（`[x]`）。完了条件は「起動して、進捗・あなた待ち・今のタスク・CI・固有の指標が 1 画面に出る。独自の状態を持たない。560px と PC 幅で崩れない」
- `dashboard/README.md`（テンプレートを写したもの）の固有指標の行を、そのリポジトリの内容に直す

### 6. PR にする

`apps-workflow:pr-flow` の手順どおり。PR 本文の「確認した証拠」は**必ず先端のコードで取り直した結果**を書く
（レビュー指摘で直したあと古い証拠を残すと、acceptance-reviewer に止められる。skill-matrix PR #55 で 2 回）。

## 複数のリポジトリをまとめて見る（ハブ）

リポジトリごとに `--serve` するとポートがぶつかり、起動コマンドも増える。`hub.mjs` を 1 本起動すれば、
`~/workspace/apps/*/dashboard/` を全部拾って `http://localhost:8790/` に一覧、`/<app>/` に各ダッシュボードを出す。

```bash
node "$(ls -d ~/.claude/plugins/cache/n-yoshida-dev/apps-workflow/*/skills/dashboard/hub.mjs | sort -V | tail -1)" --open
# オプション: --root <apps の場所>（既定 ~/workspace/apps）--port <n>（既定 8790）--host 0.0.0.0（LAN のスマホから）
#            --interval <秒>（既定 300。この間隔で 60 秒より古いアプリを裏で作り直す。0 で定期の作り直しをしない）
```

- 各リポジトリの `update.mjs` を子プロセスで呼ぶので、リポジトリごとの固有指標がそのまま出る。全部を並列に回す
- 1 アプリ 1 枚のカード。上段に進捗・あなた待ちの件数・CI・作業ツリー、下段に「今のタスク」（折り返して全文）と
  「あなた待ち」の先頭の 3 件。並びは固有の human が先、TODO の確認待ち（上から順）が後。残りは「ほか N 件」からそのアプリのダッシュボードへ。今のタスクは記法と括弧書きだけ落とした全文、押すと括弧書きも含めた原文
- 画面を開くときは手元の `data.js` をすぐ返し、作り直しは裏で行う（1 アプリ 7 秒前後かかるため。60 秒より古ければ開いたときに、
  加えて `--interval`（既定 300 秒）ごとに 60 秒より古いアプリを）。表示の「N 分前に更新」でデータの鮮度が分かる。
  「更新」「全部更新」は押した時点より後に始まった作り直しを待つ（裏の回が走っていれば、それが終わってからもう一度作る）
- 各アプリのカードの「更新」でそのアプリだけ、「全部更新」で全部を作り直す（各ダッシュボードの画面には v2.1.0 から「更新」ボタンが無い）
- ハブは各リポジトリの `--serve` を置き換えるものではない。単独で見たいときは今までどおり `--serve --open`
- ダッシュボードが無いリポジトリは一覧に出ない。足したいリポジトリで、このスキルの手順 2〜5 を行う

## 表示項目の選び方

| 出す | 出さない（または折りたたみ） |
|---|---|
| 進捗率と済み／全体の件数（TODO.md） | フェーズごとの長い表 |
| あなた待ち（TODO「確認待ち」＋固有の「人が決めるもの」） | Claude 側の作業の一覧（TODO の未完タスクで見る） |
| 今のタスク 1 件と、この後 4 件 | 未完タスク全部 |
| 開いている PR とその CI、最近のコミット 6 件（短い題名。main の CI の結果は行の先頭の記号） | CI の実行とコミットを別の欄に並べる（同じ変更が 2 行になる）・種類の札・変更ファイルの一覧 |
| 固有の指標 1〜2 個 | セッション情報・コスト（正本が無い） |
| 引き継ぎメモ・合意（折りたたみ） | 同じものを本文に展開 |

## テンプレートの構成

| ファイル | 役割 | 触るか |
|---|---|---|
| `template/update.mjs` | 正本を読んで `data.js` を書く。`--serve` で配信し、`POST /update` で作り直す。`--open` でブラウザを開く | ★ `readProjectSpecific()` だけ |
| `template/index.html` | `data.js` を読んで描く。ヘッダー（名前・いつのデータか）、異常の帯、カード、折りたたみ。題名を縮める `short()` | 原則触らない。色は `:root`。固有の指標の形が違うときだけ ★ `specific()` |
| `template/README.md` | 目的・起動・更新・取得元・構成 | 固有指標の行だけ |
| `hub.mjs`（写さない） | 全リポジトリのダッシュボードを 1 本で配信するハブ。プラグインの置き場所から直接起動する | 触らない |

TODO.md の数え方は todo-progress（apps-workflow が依存する公開版）の `scripts/progress.sh` と同じ（`##` = フェーズ、「確認待ち」「保留」「公開後」は合計から外す）。
HANDOFF.md は「現在地」「次…やること／一手」を含む `##` 見出しの節を取る。確認待ちの行の先頭の【判断】【レビュー】【作業】（`[テーマ名]` や `W<番号>` の後ろでもよい）を種類の札にする。
この 3 つの規約を変えたら `update.mjs` の該当関数を直す。

## うまくいかないとき

- **`gh` の項目が「取得できず」**：`gh auth status` を見る。未ログインでもほかの項目は出る
- **開き直しても変わらない**：ファイルを直接開いている（`file://`）。`node dashboard/update.mjs` を実行してから開き直すか、`--serve --open` で起動する。
  横断タスクボードの中なら、ops の会話で「ダッシュボード更新して」と頼む
- **数字が todo-progress の進捗表と違う**：`- [x]` の直後に空白が無い行や `##` 見出しの規約外の書き方。`readTodo()` の正規表現を見る
