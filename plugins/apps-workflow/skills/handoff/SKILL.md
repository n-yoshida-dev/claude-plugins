## 現在の状態

- 変更のあったファイル: !`git status --short 2>/dev/null || echo "(git 未初期化)"`
- 直近のコミット: !`git log --oneline -5 2>/dev/null || echo "(コミットなし)"`
- 今日の日付: !`date +%Y-%m-%d`
- HANDOFF.md の行数: !`wc -l < HANDOFF.md 2>/dev/null || echo "(なし)"`
- logs/decisions.md: !`[ -f logs/decisions.md ] && echo "あり" || echo "なし"`

## やること

このセッションの会話内容と上記の差分をもとに、次の4ファイルを更新する。
**該当することが無いファイルは触らない。** 埋めるために内容を作らない。

### 1. TODO.md

- 完了したタスクを `- [ ]` から `- [x]` へ変える
- このセッションで新たに判明したタスクを、適切なフェーズのセクションに追加する。
  タスクの次の行に半角スペース 2 つで字下げして「完了条件：」を付ける（コードを読まずに確かめられる言葉で）
- ユーザーの回答で解消した「確認待ち」項目にチェックを入れる

### 2. logs/decisions.md

このセッションで**ユーザーと合意した判断**（方針・スコープ・生活の前提・複数案から選んだ設計）があれば、
1 判断 1 エントリで追記する。ファイル冒頭のイントロと最初の `---` 区切りの**直後**（既存エントリより上）に入れる。
ファイルが無ければ `logs/` ごと作る（雛形は末尾）。

```
## YYYY-MM-DD <論点を一言で>

**論点**: 何を決めようとしていたか
**結論**: どう決めたか
**理由**: なぜその結論にしたか
**却下した代替案**: 検討して捨てた選択肢と、捨てた理由（なければ「なし」）
**確信度**: 高 / 中 / 低
**見直す条件**: この前提が崩れたら判断をやり直す、という条件（なければ「なし」）

---
```

### 3. KNOWLEDGE.md

次のどちらかに該当することがあった場合のみ追記する。

- **設計判断**：Claude が実装中に複数の選択肢から選んだこと。「なぜそうしたか」を必ず書く。見出しは `### YYYY-MM-DD：<決めたこと>`。
  ユーザーと合意した判断は、ここではなく 2 の `logs/decisions.md` へ
- **ハマったこと**：想定と違った挙動、再発しそうな落とし穴。原因と回避方法をセットで書く

コードを読めば分かることは書かない。

### 4. HANDOFF.md

**「今どこにいるか」だけを書く。目安 40 行。履歴を積まない。**

- 「現在地」を今の状態に書き換える（フェーズ・main の状態・作業中のブランチ）。前の状態を残さない
- 「次セッションで最初にやること」を、次に何から手を付けるべきかで書き直す。最初の一手だけ。一覧は `TODO.md` が持つ
- 決定事項・やったこと・申し送りは書かない。書きたくなったら行き先へ：決定は 2、ハマりと技術判断は 3、やることは 1、やったことは `git log`

古い型（「直近でやったこと」「確定している決定事項」「申し送り」の節があるもの）のアプリでは、
それらの節を**育てない**。新しい決定は 2 へ書く。節ごと移すかどうかはユーザーの判断なので、
行数が 40 を超えていたら「履歴を `logs/decisions.md` と `KNOWLEDGE.md` へ移す」を報告で提案するにとどめる。

## 制約

- **gitignore 対象のファイル（`PRIVATE.md` / `*.local.*` / `.env`）の中身をこの4ファイルに書き写さない。** 4ファイルはコミット対象
- 事実を AI 用（ルート直下）と人間用（`docs/`）の両方に書かない。AI 用から `docs/` へリンクする
- 更新が終わったら、変更点を日本語のサマリーで報告する

## logs/decisions.md がまだ無い場合の雛形

```
# 判断ログ

議論で到達した判断と、その理由・却下した代替案の台帳。
同じ論点を後で蒸し返さないために残す。新しいものほど上にある。

---
```
