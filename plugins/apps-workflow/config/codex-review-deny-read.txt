# codex-review で、Codex に読ませない場所の一覧（codex-run.sh --deny-read-list で渡す）
#
# なぜ：Codex の読み取り専用（:read-only）は、書き込みは止めるが、作業フォルダの外もどこでも読める
#   （2026-10-05 に codex sandbox -P :read-only で確かめた。/tmp のダミーとホームの下のファイルを読めた）。
#   ここに書いた場所は、権限のプロファイル（permissions.<名前>.filesystem の "deny"）で読めなくする
#   （同じ日に codex sandbox で、一覧の場所が「Permission denied」になり、作業フォルダは読め、git や grep は動くことを確かめた）
#   2026-10-06 に codex exec（新しく頼む・続き）でも、記録の上の権限に一覧の場所が deny として入り、
#   Codex は「読み取りが禁止されている」として一覧の場所を読まなかった（作業フォルダのファイルは読めた）。
#   ただし codex exec に -s を付けると、この権限が捨てられて全体を読めるようになる（codex-run.sh は -c sandbox_mode で渡す）。
#   同じ日に codex exec で、作業フォルダの中に置いた「一覧の場所を指すリンク」を cat させ、OS が「Permission denied」で止めることを確かめた。
#   サンドボックスの中ではプロセスの番号の空間が分かれていて、/proc を通ってほかのプロセスの作業フォルダをたどることもできない（codex sandbox で確かめた）
# 書き方：1 行に 1 つ、絶対パス。~ はホーム、{uid} はユーザー ID、* はその場所にあるものすべて（. で始まるものも）、
#   先頭の ! は除外。# から後ろと空行は読まない
# 注意：
#   - 読めなくした場所の中にあるものは、その下に「読める」を足しても読めない（親の deny が勝つ）。
#     そのため Codex の作業フォルダ（書き出し）は、ここに書いた場所の外（/tmp/codex-review.…）に作る
#   - codex の実行ファイル自身（VS Code の拡張機能の中）は読めるようにしておく。読めないとサンドボックスの中で Codex が起動できない
#   - ログインシェルは ~/.profile を読めないという警告を出すが、コマンドは動く

# ホームの直下は、すべて読ませない
# （リポジトリ・雑務・自分に関するデータ・会話の記録・鍵・各種ツールの設定やトークン・コマンドの履歴）
~/*
# ただし .vscode-server は丸ごとは塞がず、中を分けて、codex の実行ファイルのある extensions だけ読めるようにする
# （.vscode-server/data には VS Code の編集の履歴として .env などの写しが残るため。2026-10-06、PR #26 の 3 回目の受け入れレビュー）
!~/.vscode-server
~/.vscode-server/*
!~/.vscode-server/extensions
# Windows のドライブ（WSL。Windows 側の書類やブラウザのデータ。~/.aws などのリンクの行き先もここ）
/mnt
# Claude の作業用フォルダ（ほかのセッションのものも含む）
/tmp/claude-{uid}
